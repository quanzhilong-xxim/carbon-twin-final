# A1 数据契约与运行引擎

本阶段仅实现类型、数学映射、只读数据发布、五态互斥、Worker 生命周期与测试。未添加 AI/Mock API、快照存储实现或复杂模拟器 UI。

## 写入边界

`components/` 和 `app/` 通过 `lib/stores/DataStore.ts`、`StateMachineStore.ts` 读取快照。内部 vanilla store 与 `setState` 没有导出。ESLint 限制视图导入 `stores/internal` 或直接创建引擎。

内部能力位于 `lib/stores/internal/`，仅供控制器、生命周期 Hook 和测试使用；这属于工程误用防护，不是抵御页面恶意脚本的安全沙箱。

发布前校验原始有限数值、归一化闭区间、请求编号和世代。发布后的数据克隆、递归冻结并由 Proxy 阻断 set/deleteProperty/defineProperty/setPrototypeOf。原始值与视觉值有不同的类型、kind 和只读 Hook，但使用一次原子提交。

Sigmoid 只做演示值到视觉参数的映射，不是碳核算模型，不代表真实排放量或 IPCC 阈值。分段指数避免溢出；x、k、x0 任意非法时返回 0.5 并记录指定诊断。

## 状态与所有权

IDLE → EXPANDING/LOCKED；EXPANDING → ACTIVE/IDLE；ACTIVE → COLLAPSING/LOCKED；COLLAPSING → IDLE；LOCKED 返回取得锁之前的 IDLE 或 ACTIVE。

每项任务有独立编号和 4000ms 熔断。完成、取消或失败只清理该任务登记的资源，不操作 GSAP 全局时间线。旧编号不能完成或取消新任务。清理回调即使抛错，其余清理仍执行。

`machineHub` 发布 `lastReset` 和诊断回调；Toast 消费属于后续 UI 集成。A1 没有用弹窗掩盖底层错误，也没有增加新视觉界面。

## Worker 生命周期

根 `Providers` 在 useEffect 中创建 Worker 控制器，卸载时停止；React StrictMode 的 effect 重放创建独立实例并清理旧实例。模块导入和服务器渲染不创建 Worker。

Worker 先 INITIALIZE/READY 握手，每 200ms 发 PING。主线程每 50ms 检查，已就绪且超过 500ms 未收到心跳则恢复；首次就绪给 2000ms 启动预算。隐藏时停止超时检查，回前台先 PROBE 探活。监控本身延迟超过 250ms 时先探活并留出处理积压 PING 的机会，不把主线程阻塞误判为 Worker 死亡。事件循环繁忙时浏览器不能提供硬实时保证。

每次新建增加 generation，最新请求在主线程保留。恢复后补发最新 payload，旧 requestId/旧世代/已取消所有权的结果不发布。连续 3 次重建仍不稳定则进入 FAILED，精确释放当前业务锁。稳定心跳持续 3 秒后重置连续失败计数。停止时清理监控、文档监听、Worker 监听及 Worker 实例。

## 验证

```powershell
npm run test:a1
npm run typecheck
npm run lint
npm run build
```

测试使用已安装的 Playwright 和本机 Chrome。`playwright.a1.config.ts` 中可调整 executablePath。单元测试注入虚拟时钟与 Worker 端口；浏览器集成测试通过仅绑定 127.0.0.1 的临时测试服务器加载真实源码与模块 Worker，实际调用 terminate，再验证恢复与待处理数据重放。

测试服务器只允许固定模块清单，不读取环境变量，不作为产品路由部署。测试日志中的 `[EXPECTED error]`、`[EXPECTED warn]` 是经断言的故障注入证据，正常 build/lint 不应产生警告。测试启动器仅移除冲突的子进程颜色变量，不抑制 Node 或应用警告。

生产构建输出 `.next`，开发输出 `.next-dev`。恢复快照在 `work/a1-before-*.zip`；未修改密钥文件。后续 A2 才接流式容错和 IndexedDB，不在此提前实现。
